# Walkthrough: Microburst Seeding and Ranking Pipeline Verification

This walkthrough documents the technical steps executed, the results of the database seeding, and the API validation scores for the microburst (50 CVs + 20 Jobs) run using the 9Router embedding proxy.

## Changes & Implementation Overview

1. **9Router Monkey-Patching Integration**:
   - Built a custom `embed_chunks_9router` method in `synthetic_data/run_pipeline.py` that intercepts all internal calls to `app.services.embedding.embed_chunks`, `app.services.nmaiex_mapper_service.embed_chunks`, and `app.services.job_ingestion_service.embed_chunks`.
   - All synthetic data pipeline actions utilize 9Router (`http://localhost:20128/v1/embeddings`), preserving original native APIs for regular runtime operations.
   - Sliced the returning vectors to the required dimension size (`effective_dims`) natively in Python to comply with pgvector limitations.

2. **Polymorphic Database Constraint Correction**:
   - Removed the strict `FOREIGN KEY` constraint referencing `JOBAPPLICATION` from the `AIDOCUMENTCHUNK` table inside `database/schema_ai_core.sql`.
   - This successfully enabled polymorphic storing of chunks belonging to both CVs (pointing to `jobAppId`) and Jobs (pointing to `jobPostId` using `jobPostId` value in the `jobAppId` field for `sourceType = 'JOB'`).

3. **Unique Candidate Profile Resolution**:
   - Implemented dynamic Vietnamese contact generation in `synthetic_data/db_writer.py` to prevent `UniqueViolationError` on duplicate phones/emails generated by LLMs.

4. **Candidate Date of Birth (DOB) Generation**:
   - Integrated dynamic birth date (`dob`) generation in `write_candidate_cv` under `synthetic_data/db_writer.py`. The candidate's age is realistically derived based on their experience years (`22 + exp_years + random.randint(-2, 4)`), ensuring it is never under 18. This successfully populates the `CANDIDATE.dob` column.

5. **Job Posting Work Location (workLoc) Generation**:
   - Integrated display-friendly work location (`workLoc`) generation based on `provId` when `workMode` is `HYBRID` or `ONSITE`. Uses an exact mapper from `provId` (e.g. `HANOI` -> `Hà Nội`, `TPHCM` -> `TP. Hồ Chí Minh`) and sets `workLoc` in the `JOBPOSTING` table. Sets `Remote` if the job is fully remote.

6. **Catalog-Filtered Raw Skills (JOB_SKILL_RAW) Ingestion**:
   - Added strict filtering in `db_writer.py` before custom skills are embedded and stored in `JOB_SKILL_RAW`. Only skills that are strictly **not present** in the core database catalog table `SKILL` are sent to `embed_and_store_raw_skills`, satisfying systemic division between catalog-registered skills (Tier 1) and raw free-text skills (Tier 2).

7. **Prerequisite Configuration Interactive Checklist**:
   - Prepended a beautifully formatted interactive confirmation checklist to the top of `full_scale_execution_plan.md` to let the user or any subsequent Agent verify proxy servers, backend/frontend server status, and virtual environments (`venv`) prior to executing the 500 CV generation.
